# Повторная проверка после исправлений

Дата: 2026-09-17 · Ревизия с исправлениями: `2620ee0`

Полный прогон заново нужен **только на Windows**. На macOS и Linux основной путь уже пройден,
и трогать его целиком незачем — там проверяется ровно то, что изменилось, за 10–20 минут.

Перед началом на любой машине: обновить клон до ревизии с исправлениями и переустановить
зависимости, если менялся `package-lock.json` (он не менялся, но `git pull` стоит сделать).

```
git fetch origin
git checkout claude/wonderful-dijkstra-xf7pai   # если PR #2 ещё не влит в main
git pull
cd ai-dev-mcp-server
```

Если PR уже влит — достаточно `git pull` на `main`. Проверить, что вы на ревизии с
исправлениями: `git log --oneline -1` показывает коммит про приёмочные прогоны.

## Windows — полный прогон, 40–90 минут

На этой машине раздел B не завершался вообще, и чинили именно его блокер. Нужен весь документ
`TEST-PLAN.windows.ru.md` с начала, но с тремя уточнениями.

### Что изменилось и на что смотреть

**B2, скачивание.** Раньше установка молча стояла больше десяти минут. Теперь у загрузчика есть
окно простоя 60 секунд, и оно **перевзводится каждым пришедшим куском** — медленный канал не
режется, режется молчащий.

Два исхода, и оба — результат:

| Что увидели | Что это значит |
| --- | --- |
| Модель скачалась, `dense:doctor` → READY | Прошло. Это то, чего ждём |
| Обрыв **в течение минуты** с текстом `no data for 60s. The source accepted the connection and then stopped sending.` | Исправление работает: система больше не висит. Но сеть до CDN по-прежнему рвётся, и релиз этим не разблокирован |
| Опять висит дольше 2–3 минут без сообщения | Исправление не сработало — это самое важное, что можно записать |

Если поймали второй вариант — **запустите ещё 2–3 раза**. Каждый повтор пропускает уже скачанные
файлы и берётся только за недостающие, так что попытки дешёвые. Запишите, сколько попыток
понадобилось и докачалось ли в итоге.

**C1/C2, установка клиентов.** Раньше один пустой `mcp.json` (0 байт) ронял установку во все
четыре клиента. Теперь пустой файл читается как пустой, а поломка одного клиента не мешает
остальным — итоговый статус будет `partial`, и в нём будет видно, какой именно файл виноват.

**C3 — обязательно.** Ни на одной из трёх машин не подтверждено, что клиент реально видит сервер.
Это последний непроверенный пункт критериев приёмки. Перезапустить клиент **полностью** и спросить
у ассистента, какие инструменты `ai-dev-system` ему доступны.

## macOS — короткая проверка, ~20 минут

Раздел B здесь прошёл целиком, заново качать 600 МБ не нужно. Проверяем только изменённое.

### 1. Индекс собирается без обходного пути (главное)

Раньше здесь требовалось `AI_DEV_PYTHON=$(which python3)`. Теперь — не должно.

```bash
npm run setup
npm run doctor
```

**Ожидается:** шаг `search_index` проходит, `doctor` → `status: ok` или `degraded`, **не** `fail`.
Проверок `search_index_file`, `search_index_freshness`, `search_smoke`, `hybrid_smoke_no_dense`
в красном быть не должно.
**Записать:** `status` и все не-`ok` проверки.

### 2. Загрузчик не сломан правкой (дёшево, ~1 МБ вместо 600)

Я менял код скачивания — тот самый, который у вас отработал. Проверить его целиком незачем,
достаточно заставить его скачать один маленький файл:

```bash
rm ~/.ai-dev/models/bge-m3-onnx/config.json
npm run setup -- --dense    # должен взять только этот файл, секунды
npm run dense:doctor        # снова READY
```

**Ожидается:** докачался один файл, `dense:doctor` — шесть стадий из шести.
**Ошибкой считается:** полезло качать всё заново, или зависло, или READY не вернулся.

### 3. Мусор от убитых прогонов подметается

У вас за сессию накопилось три `.part`-файла. Теперь такие старше часа сносятся перед загрузкой.

```bash
ls -la ~/.ai-dev/models/bge-m3-onnx/onnx/
```

**Ожидается:** только `model_int8.onnx`, без `*.part`.

### 4. Конфигурация VS Code едет в правильное место

Раньше команда создавала `~/AppData/Roaming/Code/User/` — каталог, которого на маке не бывает.

```bash
rm -rf ~/AppData          # убрать мусор, который остался от прошлого прогона
node scripts/install-local-mcp-clients.mjs   # вхолостую: посмотреть пути
npm run clients:install
```

**Ожидается:** для VS Code назван `~/Library/Application Support/Code/User/mcp.json`;
каталог `~/AppData` заново **не** появляется.

### 5. C3 — клиент видит сервер (обязательно)

Единственный критерий приёмки, не подтверждённый ни на одной машине. Перезапустить клиент
полностью и спросить, какие инструменты `ai-dev-system` доступны.

### 6. Мелочи, попутно

- `npm run setup` печатает число документов, а не `? document(s) indexed`.
- Строка шага модели больше не обещает Python и 2.3 ГБ.
- `npm run doctor -- --dense-smoke` теперь действительно включает dense-проверку.
