# Приёмочное тестирование 2.1.0 — где что лежит

ТЗ рассчитано на человека, у которого **не установлено ничего** и который про MCP слышит
впервые. Начинается с установки Node и git, заканчивается работающей задачей в ИИ-клиенте.

Документ разделён по операционным системам: тестировщику выдаётся один файл целиком, без веток
«а на Windows иначе».

| Документ | Кому |
| --- | --- |
| [TEST-PLAN.macos.ru.md](TEST-PLAN.macos.ru.md) | macOS 13+, отдельно Apple Silicon и Intel |
| [TEST-PLAN.windows.ru.md](TEST-PLAN.windows.ru.md) | Windows 11, отдельно x64 и ARM64 |
| [TEST-PLAN.linux.ru.md](TEST-PLAN.linux.ru.md) | Ubuntu 22.04 / 24.04 и родственные на glibc, x64 и ARM64 |

Все команды с `npm` — дословно одинаковые на любой ОС. Различается всё, что вокруг:
установка Node, подготовка, переменные окружения, просмотр файлов, замеры, установщик Docker.
Поэтому документа три.

## Чем отличаются, кроме синтаксиса

У каждой платформы свой набор краевых случаев, которые больше нигде не проверить:

- **macOS** — карантин Gatekeeper на нативных библиотеках; Node под Rosetta на Apple Silicon
  (тогда все замеры времени несравнимы); iCloud-синхронизация домашних папок; архитектура
  вытянутого Docker-образа.
- **Windows** — PowerShell 7 против встроенного 5.1; Defender на 600-мегабайтном файле;
  домашняя папка в OneDrive; `LongPathsEnabled`; синтаксис переменных окружения
  (`VAR=1 команда` не работает); монтирование `C:\…` в контейнер.
- **Linux** — glibc против musl (на Alpine готовые бинарники, по ожиданию, не заработают,
  и нужен точный текст ошибки); `ldd` по нативному модулю; rootless Docker и SELinux
  на монтировании `/models`; домашний каталог на сетевой ФС.

## Два места, где ответ известен заранее

В документах они помечены как «известно заранее» — тестировщик должен не удивиться, а записать:

1. **Путь к конфигурации VS Code** вычисляется по правилам Windows (`APPDATA`). На macOS и Linux
   `npm run clients:install`, по ожиданию, запишет его в `~/AppData/Roaming/Code/User/mcp.json` —
   папку, которой на этих системах не бывает, — и VS Code сервер не увидит. Cursor, Claude
   и Gemini используют пути, верные везде.
2. **Свободное место перед скачиванием не проверяется**, и **корпоративный прокси** загрузчик,
   скорее всего, не увидит (для второй попытки в ТЗ дана переменная `NODE_USE_ENV_PROXY=1`).

## Главное, что нужно сказать тестировщику

Скачивание настоящих 600 МБ и загрузка настоящих весов BGE-M3 **не выполнялись ещё ни на одной
машине**: у разработки закрыт доступ к `huggingface.co`, а CI на аккаунте не запускается.
Механизм проверен на подменённой тестовой модели и работает, сами веса — нет. Поэтому раздел B
в каждом документе главный, и по нему нужны полные логи, а не «ок».
