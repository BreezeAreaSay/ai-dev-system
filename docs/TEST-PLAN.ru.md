# Приёмочное тестирование 2.1.0 — где что лежит

ТЗ разделено по операционным системам: тестировщику выдаётся один документ, целиком его,
без веток «а на Windows иначе».

| Документ | Кому |
| --- | --- |
| [TEST-PLAN.macos.ru.md](TEST-PLAN.macos.ru.md) | macOS 13+, отдельно Apple Silicon и Intel |
| [TEST-PLAN.windows.ru.md](TEST-PLAN.windows.ru.md) | Windows 11, отдельно x64 и ARM64, PowerShell 7+ |
| [TEST-PLAN.linux.ru.md](TEST-PLAN.linux.ru.md) | Ubuntu 22.04 / 24.04 и родственные на glibc, x64 и ARM64 |

## Что общего во всех трёх

Проверяются две вещи: система ставится с нуля без ручных доделок, и локальная модель BGE-M3
скачивается, проходит sha256, загружается и отвечает векторами.

Все команды с `npm` — дословно одинаковые на любой ОС:

```
npm ci --ignore-scripts --no-audit --no-fund
npm run setup
npm run setup -- --dense
npm run doctor
npm run dense:doctor
npm run verify:cursor
```

Различается всё, что вокруг: подготовка, переменные окружения, просмотр файлов, замеры
и установщик Docker. Поэтому и документа три.

## Чем отличаются

Не только синтаксисом команд. У каждой платформы свой набор краевых случаев, которые
больше нигде не проверить:

- **macOS** — карантин Gatekeeper на нативных библиотеках; Node под Rosetta на Apple Silicon
  (тогда все замеры времени несравнимы); архитектура вытянутого Docker-образа.
- **Windows** — Defender на 600-мегабайтном файле; домашняя папка в OneDrive (модель уезжает
  в облако); `LongPathsEnabled`; синтаксис переменных окружения (`VAR=1 команда` не работает);
  монтирование `C:\…` в контейнер.
- **Linux** — glibc против musl (на Alpine готовые бинарники, по ожиданию, не заработают);
  `ldd` по нативному модулю; rootless Docker и SELinux на монтировании `/models`;
  домашний каталог на сетевой ФС.

## Главное, что нужно сказать тестировщику

Скачивание настоящих 600 МБ с `huggingface.co` и загрузка настоящих весов BGE-M3
**не выполнялись ещё ни на одной машине**: у разработки закрыт доступ к `huggingface.co`,
а CI на аккаунте не запускается. Механизм проверен на синтетическом экспорте и работает,
сами веса — нет. Поэтому раздел B в каждом документе — главный, и по нему нужны полные логи,
а не «ок».
