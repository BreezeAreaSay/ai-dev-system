### 7. Влияние на установки 2.x

- **Что меняется.** Нужна Node 22.16+ или 24+ (на более старой сервер сам уходит на Python-движок, как
  в 2.x). Файл индекса — тот же; рядом `<индекс>.lock` во время перестройки. Каталог skills — 614
  вместо 3 228. Ключевые слова AND/OR/NOT/NEAR в вопросе — слова.
- **Что мигрирует само и каким тестом доказано.** Индекс 2.x читается без перестройки, векторы
  нетронуты; обновляется на месте; перестройка сохраняет векторы неизменённых документов
  (`upgrade:test`, три пользователя). Удалённые pull'ом skills сервер убирает из реестра сам, при
  первом поиске или `npm run setup` (Д-119, `upgrade:test`). Заметки опустевших подгрупп удаляются.
- **Что требует действия пользователя** (для заметки о миграции): Node 22.16+ или 24+; обновление
  как прежде — `git pull`, `npm ci`, `npm run setup`. Тем, у кого были векторы, — `npm run setup --
  --dense`: дошлёт векторы переписанных заметок групп (12 из 365 на seed).
- **Как откатиться.** `git checkout` прежнего коммита и `npm ci --ignore-scripts`: помощник 2.x
  читает индекс, который записал Node (паритет таблиц — `search:parity`); реестр skills 2.x
  перестроит из своих файлов (`npm run setup -- --force`).

### 8. Для следующих фаз и в чек-лист владельца

- Фаза 4: hybrid, галактика, `query_ui_ux_knowledge` и `run_search_eval` без Python; 6 оставшихся
  случаев freshness; удаление `search_cli.py` снимает и вопрос `flock` (отступление 7).
- Фаза 13: Docker-тома копируют seed через `cp -n` и сохранят полный каталог skills до обновления
  seed по манифесту (Д-99); `bootstrap.ps1` и минимальная Node.
- Чек-лист владельца: раздел 5 — Windows (Д-123, Д-124, Д-130, ctime), Node 22.16 на macOS и Windows,
  контейнерная половина теста обновления.
- Фаза 13: при обновлении seed по манифесту касаться обновлённых файлов и папок или перестраивать
  реестр — `cp -a -n` возвращает папкам время образа, и свежесть реестра нового skill не видит (Д-99).
- **Вопрос владельцу.** Read-only инструменты поиска (`search_all`, `search_index_status`,
  `search_skill_registry`, `recommend_skills`) через автоматическую перестройку реестра теперь пишут в
  хранилище: реестры, карточки, заметки групп. В полном хранилище эти файлы закоммичены, и вызов
  «только для чтения» может оставить рабочее дерево грязным. Оставить так (реестр всегда верен), или
  перестраивать реестр только явным `rebuild_index`/`setup` и в read-only вызовах лишь предупреждать?
