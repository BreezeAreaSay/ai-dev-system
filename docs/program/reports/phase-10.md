### 6. Отступления и принятые решения

1. **Node демона — Node клиентов.** Приложение не запускает демон своим Electron (`ELECTRON_RUN_AS_NODE`): сборка
   демона считается и по Node, и тогда у приложения был бы свой демон. Порядок — `AI_DEV_NODE`, Node из записей
   клиентов, `PATH`, места установщиков (на macOS у GUI-приложения нет `PATH` терминала); нет ни одного — экран
   «Node.js не найден» с «Повторить». Установщик фазы 12 положит свой `node.exe` и пропишет его клиентам — тот же Node.
2. **Белый список — по аргументам.** Странице доступны девять инструментов и только те аргументы, которые шлют её
   кнопки, с проверкой вида значения, обязательные — обязательны; `clients_install` — только клиенты, найденные на
   компьютере. Остальное отказывает главный процесс до демона. Фаза 11 (консоль инструментов) расширит список явно:
   каждый пишущий инструмент консоли — с подтверждением в главном процессе.
3. **Вердикт трея — проверки здоровья.** Быстрый ответ (без проверок) раз в 30 секунд лишь говорит, что что-то
   изменилось; цвет меняет только ответ с проверками — тот же, что видит «Статус», — и раз в 5 минут, и после всего, что
   меняет приложение.
4. **Контракт 1.1.0** — добавочный: `critical` и `details` у проверки, `retired` и `retired_reason` у `served_by`;
   `system_status` не перечисляет `search_smoke`, `dense_smoke`, `search_eval`, когда этот вызов их не запускал.
5. **Тексты демона — английские.** Слова приложения — на обоих языках; итог проверки, результат шага и ошибка — от
   демона, как в CLI (`docs/DESKTOP.md`, «Languages»). Исключение — совет «исправьте или удалите» на экране сбоя
   настроек: его говорит приложение, на своём языке, а фразу сервера с тем же смыслом не повторяет (Д-269).
6. **Снимки не в git** (правило 5 брифа: бинарники) — `desktop/test-results/` под `.gitignore`; отправлены в сессии.
7. **Сессия приложения держит демон**, пока приложение открыто; после «Выход» демон уходит по простою, как раньше.
8. **DevTools** — только с `AI_DEV_DESKTOP_DEVTOOLS=1`, тогда они открываются с окном; меню нет на Windows и Linux, на
   macOS — меню приложения и «Правка».
9. **Chromium приложения не разрешает имён** (`host-resolver-rules "MAP * ~NOTFOUND"`, Д-260): странице сеть не нужна,
   а имя, переданное WebRTC или `dns-prefetch`, иначе ушло бы в системный резолвер. Node главного процесса и демона
   этого правила не видят. Остаток — запрос mDNS о постоянном имени (Д-271 п. 3). Фаза 12: автообновление через
   `electron.net` получит исключение в правиле только для своего хоста.
10. **Переход с отставного демона ждёт идущих вызовов** (Д-263): загрузку, сборку, перестройку из трея дослуживает
    старый демон; «Отменено» — только то, что отменил человек.
11. **AGENTS.md поправлен раньше фазы 14**: `desktop/` в таблице мест кода и под воротами (потолок — над кодом, в тестах
    — только `eval` и `new Function`).
12. **«Остановить» верит ответу демона** (Д-273): демон, который не остановился, продолжает обслуживать клиентов, и
    приложение остаётся с ним, а не объявляет «демон не запущен»; трей говорит о сбое. Демон, который не остановился,
    может быть и не тем, на котором приложение (отставной, дослуживающий сессию клиента, или другой сборки): пометка
    держится, пока он жив, — и offline, — и «Остановить» доступно снова (Д-277). Связь действует только на свою сессию,
    с которой «Остановить» начиналось, и закрывает её, а не бросает (Д-278).
13. **Язык при испорченном файле настроек** (Д-276, Д-279): выбранный держится и записывается, как только файл его
    примет (файл смотрится дважды в секунду, пока выбор ждёт, и ещё раз при «Выходе»); если исправленный файл сам
    называет язык — действует язык файла, и решается это под замком файла. Записи — по одной, по порядку; замок
    ждётся не дольше секунды — выход и выбор не висят на чужом писателе, его ждёт следующий взгляд. Язык пишет само
    приложение — и online, мимо `settings_set` демона: так один путь, и он работает без демона.
14. **Переход с отставного демона запускает новый, только если приложению можно** (Д-276): автозапуск при старте или
    «Запустить»; иначе приложение ищет демон, как без него.

### 7. Влияние на установки 2.x

- Ничего не меняется, пока человек не поставил приложение: агент видит те же 135 инструментов, байт в байт.
- Контракт управляющего API — 1.1.0, изменения добавочные; клиенту 1.0.0 новые поля не мешают. `system_status` больше
  не перечисляет три проверки, которые этот вызов не запускал.
- Приложение подключается к тому же демону, что и клиенты, и пишет те же файлы (`~/.ai-dev/config.json`, конфиги
  клиентов — с резервной копией), что `ai-dev setup` и `ai-dev clients install`.
- Откат: удалить `desktop/` (или не запускать приложение) — сервер и клиенты работают как без него.

### 8. Для следующих фаз и в чек-лист владельца

1. **Windows 11 и macOS:** `cd desktop && npm ci && npm start` — окно и трей; цвета трея при ok / degraded / failed / без
   демона; меню трея: открыть, перестроить, остановить, выход — щелчком; на macOS — копирование и вставка через
   «Правка» и щелчок по значку в Dock; второй запуск поднимает окно первого; `npm test` (e2e) без `--no-sandbox` от
   обычного пользователя; страница не делает DNS-запросов (монитор DNS ОС, пока страница создаёт TURN и `dns-prefetch`);
   файл настроек только для чтения — выбранный язык держится, после снятия запрета записан.
2. **Живые клиенты:** мастер, шаг клиентов — Claude Desktop и Cursor отмечены, «Подключить» → перезапуск клиента →
   `ai-dev` в списке серверов, `begin_task` отвечает.
3. **Настоящие веса:** шаг модели — «Скачать» (≈ 600 МБ) с прогрессом; «Отмена» посередине; «Скачать» снова — докачка.

   консоли — подтверждение в главном процессе.
5. **Фаза 12:** упакованное приложение — сервер в `resources/ai-dev-mcp-server`, свой `node.exe` как Node клиентов;
   исключение в `host-resolver-rules` для хоста обновлений.
6. **Фаза 14:** Д-239, Д-258, Д-259, Д-267 (и Д-234 из фазы 9).
