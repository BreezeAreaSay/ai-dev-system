### 6. Отступления и принятые решения

1. **Раздел CHANGELOG — `## [3.0.0] - Unreleased`**, а не `[Unreleased]` рядом с пустым 3.0.0: версия пакетов — ещё 2.0.0
   (повышение — фаза 15, D8), а раздел описывает именно 3.0.0. При выпуске — дата вместо «Unreleased», ссылка
   `[3.0.0]` — на `v2.0.0...v3.0.0`, новый пустой `[Unreleased]` (в `docs/RELEASE.md` фазы 15).
2. **Записи «Fixed» о дефектах новых функций 3.0** (ревью фаз 3–13) оставлены в разделе: это запись того, как функции
   доводились; короткие релизные заметки — черновик фазы 15.
3. **`1036238` («запись Д-380») содержит и заметку о миграции, и удаление старых планов и `packaging/`**: они стояли в
   индексе, когда коммит записывал Д-380. Ветка уже была отправлена — история не переписывалась (без force-push); следующий
   коммит (`3de42b1`) это называет.
4. **Д-380 — правка продукта в фазе документации**: первая задача из README на новом репозитории упиралась в
   `verify_task` без пути вперёд; теперь отказ называет `prepare_project`, а `begin_task` предупреждает заранее. Маленькая и
   аддитивная — подсказка в ошибке и строка в контексте.
5. **Документация установки до публикации даёт обходные пути** (tarball для npx, свой образ для Docker) и говорит, что они
   уходят с выпуском; дословные команды README выполнены через реестр на одну запись и локальный образ.
6. **Ворота запрещённых вызовов не следят за значением дальше простого присваивания** (Д-382): имя модуля из частей,
   `createRequire`, `Reflect.get` — граница, названная в заголовке модуля и в AGENTS.md; файл, который ворота не дочитали,
   отвергается.
7. **Перенос эпохи Codex читает `.codex` своей установки** (Д-389): при `AI_DEV_HOME`, не равном домашней папке, —
   `$AI_DEV_HOME/.codex`, как читала 2.x; раньше 3.0 забирала в любой `AI_DEV_HOME` настоящий `~/.codex`.
8. **Запись Docker с моделью на другом диске не стартует без этого диска** (Д-385): Docker отвергает отсутствующий источник,
   и смонтировать «что есть» нечем; без монтирования ссылки модель не работает и с подключённым диском (Д-368). Решение —
   сказать при установке и назвать в `clients doctor`.
9. **SECURITY.md: поддерживается 3.0.x**, 2.x — нет (её образ `:2` — путь назад). Срок поддержки 2.x — вопрос владельцу
   (итоговый отчёт).
10. **Ворота запрещённых вызовов — читатель токенов, а не парсер**, и шестнадцать раундов ревью шли по ним до тех пор, пока
    новые находки не стали надуманным кодом. Каждую ошибку чтения на честном коде правили; формы, которые честный код не
    пишет, названы пределом в заголовке модуля, AGENTS.md, ARCHITECTURE и CHANGELOG. Модуль держится в 799 строках.
11. **Шестнадцатый раунд — один ревьюер** на правку пятнадцатого (`263e055`), а не три: владелец просил закончить быстрее;
    правку ворот пятнадцатого раунда ревьюер-автор уже проверил фаззерами (270 тыс. программ) и сканом.
12. **Д-403 перенесена в фазу 15**: bootstrap, заменяя запись 2.x, должен брать её папки; это меняет установщик, а не
    документацию.

### 7. Влияние на установки 2.x

- **Ничего нового в поведении**, кроме исправлений этой фазы: подсказка `prepare_project` при отсутствующей проверке проекта
