### 6. Отступления и принятые решения

1. **Синхронизация — без слияния**: `main` форка не менялся с начала сессии и уже предок ветки.
2. **Тест обновления с v2.0.0 кладёт векторы собственным `rebuild` 2.0.0** с заглушкой вместо sentence-transformers:
   ставить torch ради теста незачем, а формат таблицы — тот, что пишет сама 2.0.0 (Д-570).
3. **Векторы таблицы 2.0.0 — векторы бэкенда Python** (`python`, `unpinned`, `fp32`): у 2.0.0 другого не было; это
   те же правила, что для векторов Python поздней 2.x (D3): хранятся, ждут `setup --model` (Д-571).
4. **Версия 3.0.0 стоит в пакетах до тега**; раздел CHANGELOG — `## [3.0.0] - Unreleased`, дату ставит выкатка
   (`RELEASE.md`, раздел 3).
5. **Ревью фазы — один ревьюер**, по просьбе владельца закончить быстрее.
6. **После отчёта (решение владельца 2026-10-20): пакет npm — `ai-dev-system`, без scope**, вместо
   `@stonebridgeway/ai-dev-system`: организация в npm не нужна. Команды в разделах выше — как их прогнали тогда; сейчас
   руководства и `RELEASE.md` пишут `npx ai-dev-system` (PROGRESS, журнал).

### 7. Влияние на установки 2.x

- **Установки 2.0.0 с плотным поиском** сохраняют векторы при обновлении: они считаются векторами чужой модели и ждут
  `setup --model`, как векторы Python поздней 2.x (Д-571).
- **Docker**: повторный `bootstrap` берёт папки проектов и модели из записей, которые заменяет, — и из записи 2.x
  (`AI_DEV_PROJECT_PATH`, `AI_DEV_MODEL_PATH`); папку модели — только если в ней `bge-m3-onnx/` (Д-403). Записи с разными
  папками проектов — остановка с кодом 64, пока папка не названа.
- **Путь назад**: `:2` после выкатки (`RELEASE.md`, «Rollback»); для клона, npm и приложения — `docs/MIGRATION.md`.
