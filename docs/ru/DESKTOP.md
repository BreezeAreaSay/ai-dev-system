# Настольное приложение

Значок в трее, мастер первого запуска, экран «Статус», экраны вашей работы — проекты, расходы,
навыки, настройки, журнал демона — и консоль любого инструмента над демоном, общим для всех
ИИ-клиентов. Приложение лежит в `desktop/` и построено на Electron (решение владельца D5; версия закреплена в
`desktop/package.json`). Само оно AI Dev не запускает: оно управляет тем же демоном, к которому
приходит `ai-dev mcp` клиентов, через control API
([CONTROL-API.md](../../ai-dev-mcp-server/docs/CONTROL-API.md), на английском).

До установщика фазы 12 приложение запускается из клона:

```bash
cd ai-dev-mcp-server && npm ci && cd ../desktop
npm ci
npm start
```

Бинарь Electron скачивается при первой надобности (`npm run electron:install` скачивает его заранее).

## Что ему нужно

- **Node.js 22.16 или новее (не 23).** Демон работает на Node, и в сборку демона входит Node, на
  котором он работает: приложение запускает демон и приходит к нему с тем Node, которым пользуются
  ИИ-клиенты, иначе у клиентов и у приложения было бы по своему демону. Node ищется в таком порядке:
  `AI_DEV_NODE`; Node из записи ai-dev ИИ-клиента (то, что записал `ai-dev clients install`); `PATH`;
  места, куда его ставят установщики (`/opt/homebrew/bin`, `/usr/local/bin`, nvm, Volta,
  `Program Files\nodejs`). Не нашёлся — окно говорит об этом и какую переменную задать.
- **Сервер рядом**: `ai-dev-mcp-server/` рядом с `desktop/` в клоне или папка, которую называет
  `AI_DEV_SERVER_ROOT`.

## Что оно показывает

- **Подключение / демон не запущен.** Когда демон не запущен, а настройка `daemon_autostart`
  включена (по умолчанию), приложение запускает его, как это делает мост клиента. Если она выключена
  или запуск не удался, окно говорит, что демон не запущен, и показывает кнопку **Запустить демон**;
  неудачный запуск показывает причину и последние строки журнала демона.
- **Мастер первого запуска** открывается сам, пока индекс поиска не построен, и в любой момент — кнопкой
  **Мастер настройки** в шапке:
  1. **Папка проектов** — выбирается в системном диалоге и хранится в настройках (`projects_root`).
  2. **AI-клиенты** — найденные на этом компьютере, у каждого галочка; **Подключить выбранные**
     записывает их конфиги (`clients_install`), сначала сохранив копию каждого.
  3. **Локальная модель** — **Скачать** с прогрессом и **Отменой** (скачанное сохраняется, и
     следующая загрузка продолжает с того места), **Импортировать из папки…** — копию с другого
     компьютера или флешки — или **Пропустить**: тогда поиск работает по словам.
  4. **Поисковый индекс** — строит реестр навыков и индекс (`setup_run`), с векторами модели, если она
     есть, с прогрессом.
  5. **AI Dev готов** — что делать дальше и переход к «Статусу».
- **Статус** — работает ли установка, работает ли с тем, на что стоит посмотреть, или ещё не
  работает; модель, индекс и клиенты одним взглядом; каждая проверка здоровья с вердиктом,
  подробностями и тем, что с ней делать; **Обновить**, **Перестроить индекс** и **Запустить настройку
  снова**.
- **Проекты** — проекты, которые знает AI Dev (зарегистрированные через `register_project` или
  задачей, начатой в них), и карточка проекта: задачи с критериями, эпики — насколько продвинулся
  каждый и какую часть делать следующей, — решения, передачи, оставленные сессиями для следующей, и
  сама карточка проекта. При возврате на «Проекты» открывается та карточка, где вы остановились.
- **Расходы** — во что обошлась работа сегодня, вчера, за семь дней и за всё время: по моделям, по
  инструментам и по задачам, по всем проектам или по одному (`usage_report`). Стоимость, которую
  клиент не сообщил, — оценка по опубликованным ценам; цена снятой модели больше не проверяется.
- **Навыки** — каталог по группам, поиск и чтение навыка.
- **Настройки** — папка проектов, профили инструментов для ИИ-клиентов, зеркало для загрузки модели,
  папка модели, время простоя демона и запускает ли его приложение: у каждой — что она делает,
  какое значение действует и откуда оно, и когда изменение вступит в силу — сразу, для сессий
  ИИ-клиентов, начатых после него, или со следующего запуска демона. Изменение для новых сессий
  доходит до приложения, когда оно переподключается: **Переподключиться** открывает новую сессию, а
  демон продолжает работать. Значение, которое демон отклонил, не записывается, и показывается его
  причина. Язык выбирается в шапке.
- **Журнал** — журнал демона и его часть, отложенная при 1 МБ; **Следить** перечитывает его каждые
  две секунды, пока экран открыт.
- **Консоль** — все инструменты, которые демон показывает приложению, с пометкой *только чтение*,
  *что-то меняет* или *удаляет*; форма по входной схеме инструмента (текст, варианты, числа в своих
  границах, флажки, списки по одному на строку, JSON для остального), проверяемая до отправки; ответ —
  читаемо (имена и значения, списки, Markdown) и как JSON. Инструмент, который что-то меняет,
  запускается только после вашего подтверждения (см. «Безопасность»).

Каждый экран показывает, что идёт загрузка, говорит, почему он пуст, если пуст, и показывает ошибку
с кнопкой **Повторить**. Всё работает с клавиатуры — ссылка «Перейти к содержимому» перед шапкой,
видимая рамка фокуса, фокус на заголовке каждого экрана, — а цвета проходят WCAG AA в светлой и
тёмной схемах (это проверяет модульный тест таблицы стилей).

## Сессия приложения

Приложение приходит к демону как отдельный клиент `ai-dev-desktop`, чья сессия видит все
инструменты агента и control API (`all,control`): экраны читают через инструменты агента, а
консоли нужны все. Настройка `profiles` — то, что получают ИИ-клиенты; приложение она не сужает.

## Трей

Цвет значка — состояние демона: зелёный — всё работает, жёлтый — что-то требует внимания, красный —
пока не работает, серый — демон не запущен. Меню: **Открыть AI Dev**, **Перестроить индекс** (с его
прогрессом), **Остановить демон**, **Выход**. Закрытое окно оставляет приложение в трее; **Выход**
завершает его. Демон не принадлежит приложению: после выхода он продолжает обслуживать клиентов и
уходит сам, когда им никто не пользуется.

## Языки

Английский и русский (решение владельца D6). Язык следует системе, пока вы не выберете его в шапке;
выбор хранится в настройках (`language`), и трей следует за ним.

## Безопасность

Окно показывает только страницу самого приложения и не даёт ей ничего от Node и файловой системы:

- страница отдаётся по `app://ai-dev` только из `desktop/src/renderer` — ничего снаружи, никаких
  ссылок наружу — с Content Security Policy, которая разрешает собственные скрипты, стили и картинки
  страницы и больше ничего: ни встроенных скриптов, ни `eval`, ни сети;
- страница работает изолированно и в песочнице (`contextIsolation`, `sandbox`, без
  `nodeIntegration`); её единственный выход — замороженный `window.aiDev` из одиннадцати функций,
  каждая — один канал главного процесса;
- главный процесс отвечает на эти каналы только странице приложения. Экраны вызывают только
  инструменты, названные в `desktop/src/main/ipc-policy.mjs`, — кнопки control API и инструменты
  только для чтения, которые показывают экраны данных, — не `model_remove`, не `clients_remove` и не
  инструменты агента, которые что-то меняют;
- консоль может вызвать любой инструмент, который демон показывает приложению, но инструмент, не
  помеченный демоном как только читающий (`readOnlyHint`), запускается только после вашего
  подтверждения в системном окне сообщения, которое показывает главный процесс: инструмент, его
  аргументы и «Отмена» по умолчанию. Страница может попросить вызов, но не может ответить на это
  окно, пропустить его или объявить инструмент только читающим по своему слову;
- аргументы проверяются (простой JSON, не больше 64 КБ), у каждого вызова — id для прогресса и
  отмены;
- страница не может уйти по адресу, открыть окно или `<webview>`, запросить разрешения или начать
  скачивание, а любой запрос не к `app://` отменяется.

Защита самого демона — сокет, секрет в описателе, один пользователь — в
[SECURITY.md](../../ai-dev-mcp-server/docs/SECURITY.md) (на английском).

## Тесты

```bash
cd desktop
npm test          # модульные тесты, потом приложение целиком
npm run test:unit # только модульные
```

Сквозные тесты запускают приложение через драйвер Electron из Playwright на настоящем демоне,
каждый — в своей установке (дом, хранилище, runtime home, синтетическая модель на локальном хосте):
мастер до конца, загрузка, отменённая посередине, и состояние, которое она оставляет, экран без
демона и его кнопка запуска, экран без Node, «Статус» с проверками, русский язык, трей и то, до чего
страница не дотягивается; экраны данных с работой, которую сделал бы ИИ-клиент (проект с эпиком,
решение, передача, расходы), на английском и русском, и пустые — в свежей установке; «Настройки» —
отклонённое значение, изменение для новых сессий и переподключение; консоль — инструмент только для
чтения сразу, меняющий — отменённый, а потом подтверждённый, вызов консоли самой страницей;
клавиатура; демон, остановленный, пока экран его опрашивает. На Linux без дисплея они идут под `xvfb-run`; снимки экрана — в
`desktop/test-results/`.
