# Тест обновления

Установка линии 2.x после обновления — `git pull`, `docker pull` или переустановки — должна
работать дальше или сама мигрировать, не теряя данных. Для клона это проверяет
`npm run upgrade:test`; контейнерная половина описана ниже для CI.

## `npm run upgrade:test`

```bash
cd ai-dev-mcp-server
npm run upgrade:test                 # база: 8f647df, main прода на старте 3.0
npm run upgrade:test -- --base <коммит> --keep
```

Нужны Node 22.16+ (на более старом проверки движка поиска на Node пропускаются), git, Python 3
(на нём работает сторона 2.x; обновлённой он не нужен) и около двух минут. Во временной папке
тест:

1. выкладывает базовый коммит как git worktree и ставит его так, как документировала 2.x,
   `npm ci --ignore-scripts`;
2. создаёт состояние четырёх пользователей, у каждого свой домашний каталог:
   - **по умолчанию** — без `AI_DEV_HOME`;
   - **AI_DEV_HOME** — задан своей папкой, куда 2.x писала всё на уровень глубже, в
     `$AI_DEV_HOME/.ai-dev` (docs/DEFECTS.md, Д-90);
   - **раскладка тома Docker** — окружение, которое задаёт `docker/Dockerfile`: `AI_DEV_HOME`
     внутри домашнего каталога и явные корни состояния, индекса и артефактов, без контейнера;
   - **Python dense-бэкенд** — конфиг клиента с `AI_DEV_DENSE_BACKEND=python` и `BGE_M3_PYTHON`,
     веса torch, которые 2.x скачала в `~/.ai-dev/models/bge-m3`, и векторы с отметкой
     Python-бэкенда (3.0 этот бэкенд удалила, решение D3);

   и для каждого: задачу с чекпоинтом, решение, инстинкт, передачу сессии, поисковый индекс с
   dense-векторами — их записывает помощник 2.x так же, как его путь ONNX записывает настоящие,
   из синтетических чисел, — хуки Claude в git-репозитории и конфиги клиентов, записанные обоими
   установщиками 2.x (локальным и Docker);
3. обновляет тот же клон до рабочего дерева, как это сделал бы `git pull`, и запускает простой
   `npm ci`;
4. запускает сервер командой из конфига клиента 2.x и проверяет: задача, её чекпоинт, решение,
   инстинкт и передача находятся; движок поиска на Node читает индекс 2.x как есть — запрос
   статуса ничего не переписывает и не трогает ни одного вектора — и видит, что изменил pull:
   skills, которые он удалил (урезание каталога 2026-10-11 убрало 2 614 коннекторов), уходят из
   реестра и больше не находятся (docs/DEFECTS.md, Д-119); перестройка сохраняет байт в байт
   вектор каждого документа, который остался неизменным, а векторы ушедших и переписанных
   документов отбрасывает — среди них коннекторы Membrane, которые 2.x до исправления Д-91 тоже
   векторизовала, — оставляя переписанные следующему прогону векторизации; поиск по словам и
   гибридный отвечают; в
   `$AI_DEV_HOME/.ai-dev` ничего не осталось, хук 2.x по-прежнему запускается — а там, где его
   копия старого пути не видит перенесённую задачу, видит её после `install_agent_hooks`. Для
   пользователя Python dense-бэкенда тест проверяет ещё: `embedding_status` называет каждую
   оставшуюся настройку и одну команду, которая её заменяет; проверка здоровья предупреждает, а не
   падает; гибридный поиск отвечает, ни с чем не сравнивая векторы Python; одна команда —
   `npm run model -- import` с синтетической моделью вместо BGE-M3 — даёт каждому подходящему
   документу вектор новой модели, и индекс остаётся целым.

Каждая проверка печатает `✓` или `✗`; последняя строка — `N of M checks passed`, и любой `✗`
даёт код выхода 1.

## Контейнерная половина, для CI

Опубликованный образ 2.x скачивается не из каждой песочницы, поэтому эта половина — сценарий.
Нужны Docker, доступ к `ghcr.io` (манифесты и слои) и клон этого репозитория.

1. **Образ 2.x.** `docker pull ghcr.io/stonebridgeway/ai-dev-system:2`, когда появится
   замороженная линия `:2` (решение владельца D9). До тех пор — сборка из базового коммита:
   ```bash
   git worktree add ../ai-dev-2x 8f647df
   cd ../ai-dev-2x/ai-dev-mcp-server
   npm ci --ignore-scripts
   npm run docker:prepare
   docker build --tag ai-dev-system:2x ../.docker/build-context
   ```
2. **Том с данными 2.x.** `docker volume create ai-dev-upgrade-data`, затем запуск образа 2.x
   так, как это делает `docker/run-mcp.sh`, с томом в `/data` и git-репозиторием в `/workspace`,
   и запросы `initialize`, `begin_task`, `checkpoint_task`, `record_decision`, `save_session`,
   `search_index_status`. Записать id задачи, `indexed_document_count` и файлы в
   `/data/runtime-home/.ai-dev/.ai-dev` — то, что 2.x положила на уровень глубже.
3. **Конфиги клиентов 2.x.** `scripts/install-docker-mcp-clients.mjs --apply` из 2.x во временный
   `HOME`, с лаунчером клона.
4. **Обновление.** Тем же способом собрать текущий образ из проверяемой ветки (или скачать
   `:edge`) и указать его в `AI_DEV_IMAGE`.
5. **Проверки** — новый образ на том же томе, запущенный лаунчером, который назван в конфиге
   клиента 2.x:
   - сервер стартует и отвечает на `tools/list`;
   - `get_task` находит задачу с чекпоинтом; `list_decisions` и `list_sessions` показывают
     записанное на шаге 2;
   - `search_index_status` сообщает тот же `indexed_document_count`, без перестройки;
   - `system_health_check` сообщает `runtime_home` со статусом `ok`, а
     `/data/runtime-home/.ai-dev/.ai-dev` пуст;
   - на Windows повторный `bootstrap.ps1` пересобирает `ClaudeMcpProxy.exe`, и прокси монтирует
     `AI_DEV_MODEL_PATH` в `/models` (docs/DEFECTS.md, Д-88).
6. **Откат.** Образ 2.x на перенесённом томе по-прежнему находит состояние и индекс: образ
   задаёт их корни явно, и миграция их не трогает. То, что 2.x клала на уровень глубже, —
   например, артефакты Archify — там он больше не увидит.

Клон, откаченный на 2.x с заданным `AI_DEV_HOME`, снова ищет на уровень глубже и не находит ни
задач, ни индекса; ничего не потеряно, и переменные `AI_DEV_STATE_ROOT=$AI_DEV_HOME/state` и
`AI_DEV_SEARCH_INDEX_DIR=$AI_DEV_HOME/cache/search-index` для 2.x возвращают его к ним. Замер на
деревьях, которые оставляет `npm run upgrade:test -- --keep`: сервер 2.x находит задачу и 3 444
документа индекса в раскладке Docker как есть, ничего — в клоне с `AI_DEV_HOME` как есть, и то и
другое — там же с этими двумя переменными.

Сценарий **раскладка тома Docker** в `npm run upgrade:test` выполняет половину этого, касающуюся
данных, — сервер с окружением образа на данных, записанных 2.x, — без Docker.
